# Сдача GENESIS FinTech

Официальная [страница хакатона](https://genesis-exe.com/hackathon.html) указывает дедлайн **22 ноября 2026, 23:59 по времени Астаны** и формат: **одна ссылка на папку Google Диска с видео, кодом и описанием**, отправленная в личном кабинете с выбранным треком FinTech. Это организационная инструкция сайта; технические требования проекта описаны в `genesis.pdf`.

## Что положить в папку

1. Код: архив текущего GitHub-репозитория либо ссылка на доступную проверяющим версию репозитория. Убедиться, что в неё вошли `src`, `tests`, `episodes`, `reports`, `README.md`, `DESIGN.md`, `Dockerfile`, `uv.lock` и `LICENSE`. Проверить доступ без входа в аккаунт владельца.
2. Описание: `DESIGN.md`, `README.md` и `reports/failure_analysis.md`; при необходимости приложить PDF или текстовую копию описания. Не называть внутренний holdout официальным тестом жюри.
3. Видео: записать короткий показ рабочего запуска. Файл видео ещё не создан и его наличие нужно проверить перед отправкой.

## Сценарий видео

1. Показать название проекта и задачу: синтетическая компания, поиск финансовых ошибок агентом через публичные инструменты, независимая оценка.
2. Запустить `python scripts/run_demo_suite.py`: чистый случай, ошибка, ложное обвинение, взаимодействие, повторяемость.
3. Показать `python -m fintech_audit_rl verify --full` с итоговым количеством успешных тестов.
4. При желании открыть `python -m fintech_audit_rl desktop` и показать публичные документы, шаги расследования, submit и метрики. Это дополнительный интерфейс, не замена проверочному запуску.
5. Кратко указать ограничения: скриптовая политика написана под опубликованные шаблоны; oracle привилегирован; результаты на открытом наборе не являются оценкой на hidden set.

## Последняя проверка

```powershell
uv sync --locked --dev --python 3.11
uv run --no-sync python -m fintech_audit_rl verify --full
```

Подготовить папку Google Диска, разрешить просмотр по ссылке, проверить её из приватного окна и отправить **одну ссылку** в личном кабинете GENESIS до дедлайна. Сохранить подтверждение отправки. GitHub push или зелёный CI сами по себе не означают сдачу.
